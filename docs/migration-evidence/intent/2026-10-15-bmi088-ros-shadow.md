# BMI088 ROS observation and Pixhawk comparison

Intent: expose the PCB v3 BMI088 to ROS without changing the operational IMU,
TF authority, control or GNSS/RTCM. Firmware and ROS changes are separate
repository changes explicitly authorized by the operator for this integration.

Characterization: ESP32-S3 diagnostics type 02 contains independent MCU DRDY
stamps, raw and SI vectors, profile/IDs/validity, no orientation. Calibration
schema v1 is generated by firmware-host tools, constant bias/diagonal scales in
Bosch frame. Pixhawk adapter republishes /imu/data, and the real local EKF
consumes only angular_velocity.z via /salus/imu/data. Existing IMU selector
accepts orientation unavailable. GNSS course provides global orientation.

Decision: add tagged four-timestamp diagnostic type 03 to firmware, preserving
01/02 and v2 commands. A dedicated salus_hardware observation owner polls only
this diagnostic (never drive commands), publishes standard sensor_msgs and
loads existing calibration profiles. Both USB and ROS output are observation
only; cannot share the S3 port with controller_server. An explicit comparison
composition includes no control or automatic source switching.

Evidence to produce: pure codec/time/calibration validation, C-to-Python frame
fixture, pseudo-terminal ROS smoke with virtual firmware and synthetic Pixhawk,
focused hardware tests, full build/test and localization smoke. Physical USB
latency, sensor bias/noise, mounting TF and Pixhawk parity remain unvalidated.

Baseline: main c6bed23; firmware working tree contains the operator-authorized
uncommitted driver/calibration work. No deployment, flash or actuator tests.
